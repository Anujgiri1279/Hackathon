4. AI behavior and credit-safe limits

The implementation is wired for Gemini, OpenAI, Groq, and OpenRouter-compatible vision providers. Image requests are normalized to a maximum of 8 detected items and 8 ideas. The configured Groq placeholder model containing “not-available” is skipped, preventing a guaranteed failed request.

A live paid AI generation request was deliberately not repeated during this test. This avoids consuming credits while still verifying the complete request path, validation, provider wiring, normalization, fallback shape, and frontend rendering path. To verify a real provider once, upload one ordinary object image and wait for one result; do not repeatedly press scan.

A successful provider response, Supabase persistence, and an authenticated session require valid runtime credentials and cannot be proven from static or validation-only tests.
